# 界面与交互设计标准

在调整布局、视觉层级、地图、日历、详情、筛选或响应式行为时阅读本页。

默认入口新版地图的专项视觉与交互以根 [`AGENTS.md` 的“冒险地图设计约定”](../../../AGENTS.md#冒险地图设计约定)为准，包括彩铅材质、无常驻文字工具按钮和动画聚焦；本页的旅行杂志视觉语言用于 `/v1` 旧版，不覆盖该专项约定。历史实现记录不替代当前规范。

## 产品语气

- 这是旅行决策界面，不是宣传海报。优先显示日期、地点、交通、已确认状态、价格/条件和下一步动作。
- 删除无信息量的口号、英文 kicker、重复标题和“解释 UI 的说明文案”。有帮助的信息应靠结构、标签和状态表达。
- 避免超大 hero、无边界留白、重复外层 Card、独立路线图例和为了装饰而存在的内容块。
- 文案要具体：用“10月8日 11:00 基督城机场还车”而非“轻松返程”；用“已查目标日期 · 无可复现价格”而非含糊的“待更新”。

## 视觉语言

- 使用克制的旅行杂志感：真实目的地图片、纯色地区编码、清晰排版和轻量毛玻璃。
- 不新增渐变；状态、地区、路线和背景使用稳定纯色。触及仍有历史渐变的区域时，在不损害可读性的前提下改为纯色或透明叠层。
- 布局容器少圆角或小圆角；按钮、Chip、图片和内部控件可保留适度圆角。不要让每层嵌套都成为圆角卡片。
- 毛玻璃必须保证文字对比度，且在低性能/打印/小屏场景允许退化。
- 使用同一套 spacing、radius 和颜色 token；不要在新组件里散落近似常量。

## 信息架构

- 行程总览用“地图 + 月历”表达空间和时间；日历格内只放能快速判断当天的核心信息，详情通过点击展开。
- 同地区/同住宿连续日期使用一致颜色和连续视觉，避免用户把同一住宿误解成多次搬家。
- 页面标题、面包屑和详情返回形成层级；移动端可截断中间层，但必须保留当前项和明确返回路径。
- 搜索、筛选和地图在住宿页协同：编号用于地图定位，酒店内容进入详情，列表可独立滚动，地图在桌面保持上下文。
- 状态必须能区分已确认、推荐、备选、待核价、不可复现、明确无房和不可选择，不能只靠灰色或一个“待定”。

## 地图

- 地图必须有真实点位和路线；点位编号/标签、路线顺序、陆路/飞行/游船样式要可辨认。
- 缩放应请求或呈现对应精度，路线、箭头和点位随地图投影变化；不要只用 CSS 放大静态图。
- 自驾优先真实道路；无 key 时允许 Leaflet/OSM 或明确的退化方案，并保留“在 Google 地图打开”入口。
- 航线可用虚线或曲线；路线越晚可以更深，但不要再额外放一张重复图例卡。
- 地图交互按钮要可访问、有 `aria-label`，移动端不得遮挡内容。
- 冒险地图拖动中暂停细节补绘，但保留已完成区域；停稳后接续未完成任务，视口移出缓存时复制兼容细节，只补新露出的部分，不整批丢弃或覆盖已绘瓦片。复用仍须匹配细节层级、渲染比例和城镇数据版本，保持有界内存及后台恢复边界。
- 地图右侧中部的附近信息只在右栏、底部日历、菜单及其退出过渡均关闭时出现，展示附近地点、当前计划/推测和下一项。使用实际当前时刻与既有时区/日程，不跟随浏览日期或地图中心；首次通过图标主动开启定位，和相机定位偏好独立。只在本机内存保留最新位置，后台或面板覆盖立即清空并停止监听；恢复仅在权限仍为granted时继续，不支持权限查询则需再次点击。过期、低精度、失败与无授权退回时间计划；道路接近仅为可能在途中，不确认抵达/完成，不生成导航ETA。私密酒店仅解锁期间参与，动态地点/距离文字不得标记public持久缓存。更新限制在独立信息区，不由时间或GPS更新重绘地图；保留44px定位目标、窄屏换行及短高滚动。

- 附近信息背景以日历“整体”选中底纹为视觉参考，正文和加载失败态共用PencilSurface的wash变体，直接复用drawPencilWash，不再单独生成斜线图案。保留spacing=1.8、roughness=3.5、radius=8、inset=2和纸张色strength=1；主体覆盖范围不能向内缩小。edgeReach=8让原有连续涂抹笔触长短不齐地向外延伸，上下边缘由主笔自然起伏，不另外拼贴散笔。画布四周留12px绘制余量，滚动容器提供对应透明空间并补偿正文定位与宽度，不裁成齐边、不外扩命中区域。只画一层有颗粒、断笔和自然毛边的涂抹，不叠实心底、纸纹、外框、阴影或backdrop-filter。颜色使用当前主题--trip-paper-color而非字体墨色，文字和按钮保持原不透明度及悬浮感。稳定种子、既有铺色缓存与尺寸/主题绘制去重避免拖动或时钟更新闪变。所有尺寸生效，位置、44px操作区域和窄屏/短高滚动保持；散边参数默认关闭，不改变日历参考控件或其他共享纸面。
- 附近计划覆盖整个权威行程的全部日期、时间条目和已知地点，不按示例日期做特判；行程前后、跨日、夜间空档和无定时项目均有简洁状态及既有日程入口。跨时区航段显示起终点各自当地时间，重复航段去重；同地点多次到访按当前日期或邻近计划选择详情。未知结束时刻只作短时提醒，不生成虚假持续时间；区域点不冒充精确活动位置，GPS与计划冲突明确标注，源数据缺失保留未知。改动应核对全量来源覆盖与边界矩阵，不以几个样例通过替代全量支持。

## 日历与详情

- 已细分驾驶、休息和游览的日程，各段沿用完整的PencilSurface badge彩铅卡片，名称、计划时长和独立地点入口都在卡片内；时间由左侧刻度体现，卡片不重复起止时间，完整时段保留在无障碍名称中。驾驶分配标“预留”，不冒充导航耗时。事件只绘一张卡片，不拆成左侧比例条和右侧标签，不绘连接两者的引线。卡片边界与左轴共用分段时间映射，短停至少预留52px完整卡片空间，轴同步展开，不能让卡片错位后保留旧小时刻度；较长时段按时长增高，时点单独占位但不编造结束时间。空间不足允许单一纵向滚动；保留44px地点入口、跨日与时点语义。地图链接与选择按钮为同级控件，不嵌套也不互相遮挡，多地点不得只保留第一个。不在时间线下另加重复清单。

- 日程时间轴的空档折叠入口使用透明底、两侧共享彩铅分隔线和居中的时段/展开收起图标，不使用矩形底色、规则虚线边框或两端散排文字。展开/收起共用同一入口并保留44px点击区；空档内预留控件及边界时点空间，不能覆盖相邻事件，小时刻度过密时省略次要刻度而不改真实时刻。
- 冒险日历信息密度按实际容器宽度而非viewport分级：宽度大于1000px保留行程和天气温度，701-1000px最多两项行程与天气图标，700px及以下只保留日期和天气图标，紧凑日格固定100px高。保持七列、独立日期/天气入口和无障碍名称，隐藏事件不得残留手绘铺色或描边；全屏不把极简日格拉成长列。
- 天气徽章不显示“史/预/析”等状态字，完整状态保留在无障碍名称。天气主面板采用摘要与横向逐小时彩铅温度曲线，时间、天气图标与温度同列对应，窄屏横向滚动；点选或键盘切换时段查看降水和风速，缺测断线且不以0代替。保留当地日23/24/25小时及重复时刻的真实时间身份。代表地点说明、时区、获取时间、署名许可和模型说明进入右上actions的数据来源二级页，返回需保持日期、地图、父级、图表横向位置、选中时段和URL/history。
- 底部任务日历与地点内嵌日历不再常驻天气署名行；Open-Meteo及许可链接统一保留在天气的数据来源二级页，不占用日历滚动或交互区域。
- 天气曲线默认折叠当地00:00至08:00（含两端）的小时列，以一个可展开时段入口替代，保留09:00起的小时。折叠平均温度与09:00起的逐小时温度连续连线，用时段范围和“均/avg”区分汇总与小时值；仅缺测断线。展开保留缺测及夏令时重复小时，纵向刻度始终取完整当地日。来源子页返回保留展开状态，收起当前选中的凌晨小时后选择可见日间小时。
- 折叠天气时段显示已有有效小时气温的算术平均值，保留一位小数并标注“均/avg”；0和负温参与计算，缺测不当作0，全部缺失显示“--”。提示和无障碍名称给出有效小时数/总小时数；平均值使用完整当地日的同一纵轴并接入温度曲线。
- 天气时间轴不再单独显示“当地时间 / 气温 °C”表头，单位保留在摘要、时段详情和无障碍名称；展开后的收起入口放在时间轴首列，不另占一行。小时列随全日曲线底部收紧，仅保留笔迹安全边距，折叠/展开不改变纵轴或详情的垂直位置。
- 跨地点当日天气沿同一横向时间轴拼接，标明地点分段，只有一份选中时段详情，随选择显示对应地点、时间、天气、降水和风。已有出发和抵达时刻之间的空段可按用户确认的中点规则分配起终点天气；来源二级页明确这是端点近似，不是沿路实测。日历保留多地点图标及完整无障碍名称，不重新铺两份图表和详情。
- 多地点天气摘要固定为天气图标、可收缩文字、44px刷新按钮三列，刷新按钮不另起一行；天气面板内容宽度不超过440px时，各地点摘要上下排列，保留各自右侧刷新入口。
- 地点酒店标题下留小间距并复用彩铅分隔线；外层地点 tabs 上下留白保持紧凑统一。所有事件的行程安排 tab 仅保留时间线，不挂载执行事项列表、地点/车程概述、当日总结或备选说明等附加段落；保留时间线选择和返回状态，源数据、其他 tab 和旧版独立组件不受影响。
- 使用真实月历七列网格，保持星期和日期对齐；不能用一列卡片冒充日历。
- 所有路线详情正文仅保留既有当天安排时间线，分段路线沿用其日程范围和途经点点击入口；不显示额外标题、行进路线图、道路加载说明、途经点覆盖或来源与限制。顶部日期、里程、预估耗时和操作按钮保留，地图来源统一从背包子页查看，底层路线元数据不删除。
- 点击日期负责选择行程区域或当天；点击事件负责打开事件详情，两种动作不要混淆。
- 详情使用可分享 URL。事件、酒店、活动和图库的打开、tab、关闭、浏览器前进/后退都应恢复一致状态。
- 详情图使用真实本地图，头图、房型图、公共区域图明确区分；全屏图库保留来源和缩略图导航。
- 移动端详情可全屏；标题单行或有控制的截断，关闭/返回按钮始终可见，内部 Card 不得被全屏选择器误伤。

## 响应式与无障碍

- 至少验证桌面、平板和约 436px 手机宽度；无横向滚动，七列日历必要时隐藏次要文案而非破坏列宽。
- 可点击的非原生元素应改为 Button/ButtonBase 或提供键盘、焦点和 ARIA 行为。
- 不仅靠颜色传达状态；配合文字、图标或边框。
- 图片有准确 alt；外链标识、新窗口行为和加载失败状态清楚。

## 验收问题

1. 用户能否在几秒内回答“哪天、去哪、住哪、是否确认、还要做什么”？
2. 是否存在重复标题、重复卡片或只为解释 UI 而存在的文案？
3. 地图/日历/详情是否在缩放、刷新、返回和手机尺寸下仍一致？
4. 状态和证据是否具体，还是视觉上掩盖了未知？
