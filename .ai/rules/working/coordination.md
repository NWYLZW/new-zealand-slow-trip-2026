# 并发、Agent 与共享工作区协调

在决定是否并行、分派批量调研或整合多人结果时阅读本页。

## 先判断是否值得并行

适合并行：

- 子任务边界稳定、输入明确、输出互不依赖；
- 每个子任务修改不同文件或只返回研究结果；
- 有清晰的集成者和全局门禁；
- 并行能显著缩短等待时间。

不适合并行：

- 多个任务争抢同一 IAB、登录态 tab、端口或动态网站会话；
- 多个任务会修改同一聚合文件、同一 schema 或同一图片 manifest；
- 需求/样例还未定型，schema 很可能变化；
- 用户明确要求少 agent，或历史上并发已导致挂起/覆盖。

本项目的登录态浏览器研究默认单线程。批量静态审计或互斥地区文件可谨慎并行，但需要集成审查。

## 分派契约

每个子任务必须写清：

- 唯一范围和不应触碰的文件；
- 输入事实、查询条件和证据标准；
- 输出格式：只回报告还是允许编辑；
- 禁止事项：不提交、不推送、不预订、不修改共享入口等；
- 必须运行的局部验证；
- 何时停止并向主任务报告歧义。

不要让两个 agent “都看看整个问题”，这会产生重复研究和冲突写入。

## 共享工作区

- 所有改动即时可见，先检查其他任务状态再修改共享文件。
- 分区文件优先：地区数据各自维护，聚合入口由一个集成者统一修改。
- 子任务不 commit/push，除非明确授权其独占交付；主任务统一审查和提交。
- 不用 reset/checkout/clean 解决冲突；区分自己的改动、用户改动和其他 agent 改动。
- 子任务完成不代表全局完成。集成者必须读 diff、核对证据、运行跨域审计和浏览器验收。

## 结果整合

1. 收集所有子任务状态，确认没有仍在写相同文件的任务。
2. 审查每个变更的来源、查询条件和状态语义，不只看“已完成”声明。
3. 处理重复 ID、重复图片、冲突选择、字段漂移和聚合 export。
4. 运行全量门禁；局部测试不能证明跨地区/跨页面契约。
5. 用户变更优先级或说“不要太多 agent”时，停止新增并行，收回到单线程。

## 失败处理

- agent/tool 超时先检查文件和本地审计；工具失败不等于其改动失败，也不证明成功。
- 无法确认某个子任务是否仍在运行时，不在其文件上盲目覆盖。
- 并发带来的返工超过收益时，记录原因并将该类任务默认改为串行。
