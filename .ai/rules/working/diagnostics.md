# 分层诊断与失败恢复

在白屏、构建失败、服务停止、浏览器/IAB 超时、网页无数据、工具卡住或审计失败时阅读本页。

## 先定义观察，不抢答根因

把“看到什么”与“为什么”分开：

- 观察：入口白屏、iframe 存在、静态 HTML 可取、控制接口超时。
- 假设：重定向、样式、嵌入策略、端点发现、权限桥接等。
- 证据：HTTP 状态、DOM、控制台、日志、监听者、最小复现。

没有证据时说“当前最可疑”，不能说“已锁定根因”。新证据反驳旧判断时明确撤回，不沿着旧叙事继续操作。

## 故障层级

按从便宜到昂贵的顺序隔离：

1. **输入层**：URL、日期、参数、环境变量、当前目录是否正确。
2. **文件/数据层**：资源存在、schema、导入、生成数据和敏感字段。
3. **构建层**：依赖、编译、base path、静态资源解析。
4. **服务层**：进程、端口、HTTP 状态、HMR/预览模式。
5. **页面层**：DOM、样式、控制台、网络请求、响应式布局。
6. **外部网站层**：登录、风控、动态加载、地区/币种、库存系统。
7. **控制工具层**：IAB/Chrome 发现、tab、权限、插件、工具超时。
8. **系统层**：只有充分证据且有明确授权才触及。

每次只改变一个变量，用能够区分两个假设的测试推进。

## 最小复现与独立证据

- 服务问题：先 `curl`/HTTP 200，再看浏览器；浏览器控制失败不等于服务挂了。
- 页面问题：直接打开最终路径，区分外层嵌入和内页内容。
- 构建问题：确认依赖已安装；`command not found` 是环境缺依赖，不等于源码失败。
- 数据问题：运行专项审计并抽查原始对象；审计脚本自身也需确认覆盖目标。
- 工具问题：测试“获取工具 → 列资源/tab → 读取简单对象”三个阶段，定位卡点。

最终结论至少由两类独立证据支撑，或由一个足够直接的权威证据支撑。

## 安全恢复阶梯

1. 重取当前状态/快照，修正 locator、变量名、工作目录或命令参数。
2. 终止仅由本任务启动且明确卡住的命令/临时 tab。
3. 重新启动项目本地服务或重连受支持的产品入口。
4. 使用产品正式的重启、设置、更新或用户操作。
5. 需要改系统进程、socket、临时目录、插件文件时停止并请求明确授权；默认不做。

不要因为等待 API 用错就连续发送多条“继续/马上执行”消息；先回收会话或改用一个可控的短命令。

## 失败预算

- 同一路径连续两次没有新增证据时，停止机械重试，换一层或换一个可区分假设的测试。
- 第三次仍是同一外部阻塞且没有安全替代时，准确报告阻塞；不要扩大系统操作来证明努力。
- 可并行做的本地分析、数据整理或文档工作继续推进，但不能伪造被阻塞的实时结果。

## 修复后的验证

- 验证原始症状消失，而不是仅看到某个进程/文件变化。
- 检查相邻功能和回退路径。
- 记录根因、触发条件、最小修复和防复发门禁；只有会复发且证据稳定时才沉淀长期规则。
