# 私密行程保险箱

这个站点的公开内容继续保存在普通数据文件中。订单号、准确地址、房东联系方式、入户说明和私人图片等信息应放在私密保险箱中；Git 与 GitHub Pages 只会收到密文。

## 首次创建密文

1. 在仓库外的私密位置创建一个 JSON 文件，例如 `~/Documents/private-vault.json`。顶层必须是对象；下面是安全的结构示例，示例内容不应复制为真实订单：

   ```json
   {
     "accommodations": {
       "hotel-queenstown": {
         "地址": "在此填写准确地址",
         "确认信息": "在此填写订单号"
       }
     },
     "flights": {
       "MH0523": { "订位信息": "在此填写" }
     },
     "rentalCars": {
       "south": { "租车订单": "在此填写" }
     },
     "activities": {
       "hobbiton": { "活动订单": "在此填写" }
     }
   }
   ```

2. 运行：

   ```bash
   npm run vault:encrypt -- /绝对路径/private-vault.json
   ```

   命令会在终端中两次隐藏输入恢复口令，并把**仅含密文**的 `src/data/privateVaultPayload.js` 写入仓库。恢复口令不会写入文件或输出。

3. 检查 `git diff src/data/privateVaultPayload.js`：只能看到 `salt`、`iv`、`ciphertext`、算法参数和创建时间，不能出现任何地址、订单号、姓名或口令。确认后才提交并推送。

4. 确认私密源 JSON 不在 Git 中；仓库 `.gitignore` 已覆盖常见的 `private-vault.json` 命名，但放在仓库外更稳妥。

## 在网站解锁

在左侧 sidebar 的空白区域持续长按 10 秒，才会出现解锁框；松手、移出 sidebar 或操作导航控件都会取消。第一次输入恢复口令后，浏览器会创建一对不可导出的 RSA-OAEP 设备密钥，并把被该设备公钥包裹的数据密钥放到 IndexedDB。之后在同一浏览器、同一正式站点域名下可直接解锁，不再需要选择文件或输入恢复口令。

解锁后的字段不会汇总成独立页面：它们只会显示在对应的已确认住宿详情、航班详情、租车详情和活动详情中。JSON 中省略某个项目键时，那个详情不会显示私密区块。当前住宿键为 `hotel-queenstown`、`hotel-wanaka`、`mount-cook`、`hotel-oamaru`、`hotel-christchurch`、`hotel-auckland-city`；航班键使用页面上的航班号；租车使用 `south`；活动使用页面 URL 中的 `activity` ID。

“立即锁定”只清除当前页面内存中的明文；“移除此设备”会删除 IndexedDB 中的设备私钥和被包裹的数据密钥。使用共享设备时不要选择信任设备。

## 恢复与更新

- 清理浏览器站点数据、使用新设备或更新保险箱后，使用恢复口令重新解锁并信任新设备。
- 每次运行加密命令都会生成新的随机数据密钥，因此已有设备需要用恢复口令重新信任一次。
- 丢失恢复口令且所有已信任设备也被清除后，密文无法恢复；请把恢复口令存入可信密码管理器或离线安全位置。
- 私钥、恢复口令和原始私密 JSON 不得提交、截图、粘贴到 issue 或发送给自动化工具。

## 加密格式

明文由随机 AES-256-GCM 数据密钥加密。恢复口令经 Argon2id（19 MiB、2 次迭代、并行度 1）派生出密钥加密密钥，用来包裹数据密钥。信任设备时，浏览器生成 RSA-3072-OAEP/SHA-256 密钥对，私钥作为不可导出 `CryptoKey` 留在 IndexedDB 中。每次 AES-GCM 加密使用新的 96 位随机 IV，并绑定格式版本作为附加认证数据。

这保护的是 Git、GitHub Pages 和普通访客。拥有仓库写权限或能在该浏览器同源执行脚本的人仍可能诱导或读取已解锁数据；请限制写权限、审阅部署改动，并及时锁定共享设备。
